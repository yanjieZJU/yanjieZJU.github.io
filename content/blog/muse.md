## 引子

之前在面试的时候被问到一个问题：OpenClaw 和 Workbuddy 这些 ToC 的 Agent 有什么区别？

我之前的理解是 OpenClaw 作为一个开源框架，优势在于定制空间大，但使用的门槛也更高。而 Workbuddy 首先是一个 APP，用户开箱即用；其次，它通过封装大量的「专家 Agent」、SKILL 和 MCP，使得用户可以快速实现自己的业务逻辑。

下面是面试官的补充：

OpenClaw 定义为个人助理，它的角色定义、记忆都是围绕你这个人的；而 ToC 的 Agent 面向十万/百万级别的用户，无法做到「一人一定义」，即便它的记忆是基于用户的，但这类 Agent 的角色定义、能力定义是通用的。

我听到这里有种恍然大悟的感觉，原来即便是统称为「个人助理」，他们之间也有如此明显的差异（后来想想其实 ToC Agent 可能也不能够称为个人助理）。

后来，我又注意到了 Meta 推出的 Muse。它同样被定位为 Personal Agent，强调的是「帮你做事」。这让我产生了新的疑问：Muse 和 OpenClaw、WorkBuddy、千问 APP，以及之前的 Manus、MiniMax Agent，到底有什么区别？如果这些产品在我看来都可以算是某种个人助理，那么为什么 Muse 会引起这么大的关注？

这篇笔记就从这个问题出发，尝试通过 Muse 重新理解 Personal Agent。需要说明的是，我没有实际使用过 Muse，以下对它的分析主要基于公开的产品介绍和设计文章，以及我自己的理解，并非实际体验。

## 从几个 Agent 开始看
我发现，自己会很自然地把 Manus、OpenClaw、WorkBuddy 和 Muse 放在一起比较。

Manus 可以在云端执行复杂任务，OpenClaw 可以部署在本地，Muse 也有自己的云端执行环境。WorkBuddy 则从办公场景切入，专门在你本地的工作空间和文件夹中进行办公任务。它们的产品形态、使用门槛和目标场景各不相同，但都在尝试帮用户完成事情。

那么，能够帮用户完成任务，就可以被称为 Personal Agent 吗？

我现在觉得可能还不够。如果只看任务执行能力，那么通用 Agent 也能完成大量复杂任务。即便它并不了解用户是谁，也可以根据当前指令规划步骤、调用工具并交付结果。

面试官提到的区别让我开始关注另一件事：这个 Agent 究竟是在执行一个用户临时交代的任务，还是在长期服务于一个具体的用户？

这也让我重新理解了「个人」二字。它可能不只是指用户可以自己安装、配置或使用这个 Agent，而是指它的角色、记忆和行动能够在多次交互中，逐渐围绕同一个人建立起连续性。

## Muse 的产品拆解

### 让用户生活更美好
Muse 的定位更像是生活上的个人助理，官方介绍中提到的任务包括整理邮件、规划行程、挑选商品等。在 Muse 的公开设计文章中，作者提到它的系统提示词第一句是：

```Your purpose is to make your user's life better.```

这点还挺有意思的（至少我自己不会用「让用户生活更美好」来定义它的目的）。它给了 Agent 一个更高层次的目标，以及明确了 Agent 应该站在什么立场上帮用户完成任务。

### 真正的个人助理
Muse 的产品形态和功能也使得它更接近「个人」。

首先是跨对话记忆。Muse 会保留关于用户的信息，并允许用户查看和编辑记忆文件。

其次是长期目标与主动建议。Muse 能够围绕用户的目标跟进进展，也会根据过去的对话和偏好提出建议。这样一来，用户与它的关系就不必局限于一次提问和一次回答，而可以跨越多次交互继续发展。

我觉得这两点比较贴近自己对 Personal Agent 的初步理解：它不只是完成当前的一次性请求，还要在交互过程中持续地了解用户，并在之后的任务中利用这些信息。

### 交互式输出
这是另一个让我感兴趣的特点。传统聊天界面主要以文本为中心，但文本并不总是最适合承载任务结果的形式。例如，用户可能需要比较多个方案、浏览和筛选信息，或者直接操作一个生成出来的内容。此时，输出就不只是供人阅读的答案，也可以成为用户继续探索和操作的界面。

这和我之前做的 ArchCanvas 项目起点也是一致的。就是当系统设计主要通过文本交流时，概念中的功能模块和数据流可能不够直观，用户也很难直接检查和修改这些结构。

因此，我对交互式输出感兴趣的地方，不只是它能够生成更丰富的界面，而是它可能改变用户与 Agent 协作的方式：用户不必总是通过语言描述下一步操作，也可以直接在结果上进行探索、比较和修改。

当然，交互式输出并不是 Muse 独有的能力。ChatGPT 此前也在探索 Intelligent UI，通过组合预定义组件，根据用户意图动态呈现界面。我认为这种交互形式会成为（或者已经成为）人与 Agent 交互一种重要的方式。

## 回到 Personal Agent 的概念
经过这次梳理，我对 Personal Agent 的理解有了一些变化。一开始我主要从任务执行能力来理解 Agent。只要它能够规划任务、调用工具并交付结果，我就很容易把它归入个人助理的范畴。

但现在，我觉得「个人助理」可能更强调它与用户之间的长期关系，而不只是它能够完成多少任务。它至少应当包含下面两个特征：

1. 持续理解一个具体用户。 不只是保存用户过去说过什么，还要能在不同任务中利用用户的偏好、习惯和长期需求。

2. 围绕用户的目标持续推进事情。 不只响应一次性的指令，还能在适当授权下记录进展、继续执行，并根据变化调整行动。
